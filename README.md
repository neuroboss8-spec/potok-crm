# Поток CRM

Мини-CRM для заявок одного агентства. Клиент оставляет имя, контакт и запрос в вашем Telegram-боте; сотрудник работает с заявкой в браузере. Можно создать заявку вручную, назначить теги, искать и фильтровать обращения, менять этапы воронки, указать сумму сделки и дату следующего контакта.

Это самостоятельная устанавливаемая версия без готовых аккаунтов, клиентской базы, чужого токена бота или привязки к серверу автора. Приложение рассчитано на одну организацию с владельцем и проверяющим пользователем.

## Возможности

- Telegram-анкета с проверкой ответов перед отправкой, сохранением черновика и защитой от повторного подтверждения.
- Общая база PostgreSQL для бота и веб-приложения.
- Таблица заявок, поиск и совместимые фильтры по тегам, источнику и статусу.
- Карточка заявки, цветные теги, ручное создание и редактирование.
- Канбан с девятью этапами, перемещением заявок, суммами по колонкам и созданием сделки из этапа.
- Календарь следующего контакта и адаптивный интерфейс.
- Django sessions, CSRF, ограничение попыток входа; свободной регистрации нет.

Обычный личный Telegram-аккаунт не подключается. Вложения, рассылки, мультиорганизации и интеграции с другими CRM не реализованы.

## Установка через Docker

Нужны Git, Python 3.12+ для генерации конфигурации и Docker Compose v2. На Windows запустите Docker Desktop с Linux-контейнерами.

```sh
git clone https://github.com/neuroboss8-spec/potok-crm.git
cd potok-crm
python scripts/configure.py
```

Скрипт создаёт `.env` с новыми случайными ключом Django и паролем PostgreSQL. Существующий файл не перезаписывается. Если Python не установлен, скопируйте `.env.example` в `.env` и самостоятельно задайте случайный ключ Django (минимум 50 символов) и одинаковый пароль БД в `PG_PASSWORD` и `DATABASE_URL`. При использовании символов URL в пароле его необходимо URL-кодировать в `DATABASE_URL`.

```sh
docker compose build
docker compose up -d db
docker compose run --rm web python manage.py migrate
docker compose run --rm -it web python manage.py bootstrap_users
docker compose run --rm web python manage.py seed_demo
docker compose up -d web
```

`bootstrap_users` предлагает задать собственные пароли для `owner` и `reviewer` (минимум 12 символов). Общего пароля нет; существующим пользователям команда пароль не меняет. `owner` имеет доступ к Django admin, `reviewer` — к рабочей CRM.

Откройте **http://localhost:8000/**. Главная страница — воронка; `/leads/` — все заявки, `/calendar/` — календарь, `/doc/` — описание, `/guide/` — проверочный сценарий.

Команда `seed_demo` необязательна: она создаёт или обновляет только 12 вымышленных записей, помеченных `is_demo`, с контактами `example.com`. Повторный запуск не размножает набор. Их можно убрать командой:

```sh
docker compose run --rm web python manage.py reset_demo
```

Обычные заявки при этом не удаляются. Перед использованием реальных данных установите `DEMO_MODE=0`.

## Свой Telegram-бот

Создайте бота через Telegram **@BotFather**. В закрытом `.env` заполните `BOT_TOKEN` и `BOT_USERNAME` (имя без `@`), затем запустите:

```sh
docker compose up -d bot
docker compose logs --tail 30 bot
```

Бот использует long polling: входящий webhook не требуется. Для одного токена должен работать только один poller. Без токена бот намеренно не запускается; CRM и ручной ввод работают отдельно.

Проверка вашей установки:

1. Отправьте `/start` своему боту, укажите имя, контакт и запрос, подтвердите анкету.
2. В CRM найдите новую запись, добавьте тег и отфильтруйте по нему список.
3. Создайте заявку вручную с тем же тегом, проверьте поиск и совмещение фильтров.
4. Измените этап, сумму или дату контакта, перезагрузите страницу.
5. Перезапустите свои контейнеры (`docker compose restart`), убедитесь в сохранности записей. Не используйте `down -v`: этот флаг удаляет том с БД.

Этот сценарий нужно пройти со своим токеном и сервером: наличие кода и автотестов не подтверждает живую интеграцию конкретной установки.

## Публикация на сервере

Для внешнего доступа нужен ваш сервер, домен и reverse proxy с HTTPS. Пример Caddy в `deploy/Caddyfile.example` предполагает, что Caddy работает на хосте сервера. Web слушает только `127.0.0.1:8000`; PostgreSQL наружу не публикуется.

В `.env` задайте `DJANGO_DEBUG=0`, `DEMO_MODE=0`, `ALLOWED_HOSTS=crm.example.com`, `CSRF_TRUSTED_ORIGINS=https://crm.example.com`, `PUBLIC_BASE_URL=https://crm.example.com`. Сохраните ранее сгенерированные секреты; не используйте пароли из примеров. Reverse proxy должен самостоятельно устанавливать доверенный `X-Forwarded-Proto`, не принимать его произвольное значение от клиента. После изменения переменных пересоздайте web/bot (`docker compose up -d --force-recreate web bot`).

Для установки Django по HTTPS без proxy в Compose локальная конфигурация с `DEBUG=1` не подходит. При `DEBUG=0` защищённые cookies и перенаправление на HTTPS включаются автоматически. Health-check: `/healthz/` (только `ok` либо `unavailable`). Настройте отдельное закрытое хранение резервных копий PostgreSQL и проверьте восстановление перед загрузкой клиентских данных.

## Проверки разработчика

```sh
docker compose run --rm web python manage.py check
docker compose run --rm web python manage.py makemigrations --check --dry-run
docker compose run --rm web python manage.py test crm.tests
```

Стек: Django 5.2, PostgreSQL 16, aiogram, htmx и локальные Tabler-совместимые стили. Python-зависимости закреплены в `requirements.lock`; источники и лицензии сторонних компонентов перечислены в [THIRD_PARTY.md](THIRD_PARTY.md).

Исходный код распространяется по MIT; лицензии сторонних компонентов сохраняются. Можно установить, адаптировать и использовать для своих проектов.
